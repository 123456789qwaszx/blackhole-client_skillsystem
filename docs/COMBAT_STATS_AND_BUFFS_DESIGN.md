# 스킬 공통 전투 수치와 천체 처치 버프 — 기획 명세

작성일: 2026-09-25 · 구현 반영: 2026-09-26  
적용 대상: `skill-only-sandbox`의 Breaker, PiercingLaser, 천체 사망 효과  
상태: **전투 수치 명세와 구현 기준**. 현재 브랜치의 구현 범위·한계는 9절에 명시한다.

## 1. 플레이 경험과 범위

플레이어는 포인터로 자동 공격의 위치를 정하고, 특수 천체를 직접 파괴하면 짧은 시간 동안
공격이 빨라지거나 치명타가 확정된다. 한 천체의 처치가 전투 리듬을 잠시 바꾸는 것이
목적이다. 효과가 끝나면 별도 조작 없이 원래 공격 리듬으로 돌아간다.

이번 명세는 **스킬 공격의 공통 수치**와 **처치로 얻는 AttackHaste·GuaranteedCritical**의
적용 범위를 결정한다. 천체의 폭발·연쇄 번개 피해 규칙은
[기존 스킬 시스템 명세](SKILL_SYSTEM_SPEC.md)를 따른다. 골드 획득 배율과 골드의 치명타는
전투 공격 치명타와 별개이며, 이번 범위에 넣지 않는다.

## 3. 용어와 데이터의 소유권

| 대상 | 소유하는 값·상태 | 이 값으로 결정하지 않는 것 |
| --- | --- | --- |
| 스킬 정의 | `Damage`, `Interval`, 고유 판정 형상. Breaker는 `Radius`, Laser는 `Width`·`TelegraphDuration` | 플레이어가 지금 어떤 버프를 받았는지 |
| 플레이어 공통 전투 수치 | 치명타 확률 `CritChance`, 치명타 피해 배율 `CritMultiplier`, 공격 간격 배율 `IntervalMultiplier` | 원형/직선 판정, 천체의 사망 효과 |
| 버프 실행 상태 | 소유 `PlayerId`, 종류, 강도, 남은 시간 | 스킬의 기본 수치와 SO 원본의 변경 |
| 적의 사망 효과 정의 | 처치 시 어떤 버프를 어떤 수치·기간으로 줄지 | 누구에게 적용할지. 처치자 `PlayerId`가 그때 결정한다 |

`CritChance`와 `IntervalMultiplier`는 **공통 공격 수치**이지 `SkillType`이나 별도의
“치명타 스킬”이 아니다. Breaker와 Laser는 각각 고유한 공격 방식을 실행하고, 공통 수치를
공격 시점에 조회한다. 이 두 스킬을 묶기 위한 새 인터페이스를 만들지 않는다.

나중에 노드 수치 주소를 연결한다면 `Player.CritChance`, `Player.CritMultiplier`,
`Player.IntervalMultiplier`와 `Skill.Breaker.Damage`, `Skill.Laser.Width`처럼 **값의
적용 대상**을 구별한다. 특정 스킬만 강화하는 콘텐츠가 생길 때 해당 스킬 주소를 추가한다.
주소의 저장 형식·노드 구매 규칙은 여기서 확정하지 않는다.

## 4. 스킬별 공통 수치의 적용 범위

| 판정 | Breaker | PiercingLaser | 천체 사망 효과 피해 |
| --- | --- | --- | --- |
| 공격 주기 배율 | 공격 Tick 간격에 적용 | **예고 시작 간격**에 적용 | 적용 안 함 |
| 치명타 확률·확정 치명타 | 적중한 공격 1회에 적용 | **발사 순간**의 공격 1회에 적용 | 적용 안 함 |
| 치명타 피해 배율 | 치명타가 난 직접 공격에 1회 | 치명타가 난 직접 발사에 1회 | 적용 안 함 |
| 공격 형상 | 포인터 중심 원, 반경 안 모든 적 | 예고 시 확정한 직선, 발사 시 경로 안 모든 적 | 별도의 폭발·번개 규칙 |

Laser의 `TelegraphDuration`은 예고가 보이는 시간이다. Haste가 주기를 줄여도 **이미
시작한 예고의 길이나 방향은 바뀌지 않는다.** 예고 중 버프가 생기거나 끝나면 그 이후의
예고 시작 시각에만 영향을 준다. 치명타 판정은 예고 시작이 아니라 **발사 시점**의
버프 상태를 본다.

## 5. 전투 수치와 치명타 계산

### 5.1 확률과 피해

- `CritChance`는 0.0~1.0 범위다. 0은 발생하지 않음, 1은 항상 발생함이다.
- 첫 밸런스 기준은 `CritChance = 0`, `CritMultiplier = 2`다. 현재 스킬 기본 피해와
  천체의 버프 시간·강도는 SO의 샘플 값을 사용한다. 이 값은 측정 후 조정할 수 있지만
  **수치의 의미와 계산 순서**는 바꾸지 않는다.
- 노드 등 영구 강화로 얻은 확률과 유효한 한시 확률 보너스를 더한 뒤 0~1로 제한한다.
- `GuaranteedCritical`이 활성화되면 최종 확률을 **1로 설정**한다. 확률 보너스를
  더하거나 피해 배율을 별도로 더하지 않는다.
- 직접 공격의 최종 피해는 `기본 스킬 피해 × (치명타면 max(플레이어 CritMultiplier, 현재 버프의 CriticalMultiplier), 아니면 1)`이다.
  다른 피해 보정이 도입되면 그 연산 순서를 별도 명세로 확정한다. 현재는 방어력·취약
  배율이 없다.

### 5.2 다중 대상 공격의 판정 단위

**공격 실행 1회당 치명타를 한 번 판정한다.** Breaker의 한 Tick 또는 Laser의 한 발이
여러 적을 맞혔다면 그 공격에 맞은 적은 모두 같은 치명타 결과를 받는다.

- 유효한 적중 대상이 없으면 치명타 난수를 소비하지 않는다.
- 유효 대상이 생기면 첫 피해를 적용하기 전 그 공격의 치명타 결과를 확정한다.
- 피해를 받은 적의 수만큼 확률을 다시 굴리지 않는다. 고정 seed와 동일한 공격 입력은
  적 배치 순서가 같을 때 같은 결과를 만든다.
- 레이저 시작점 난수와 치명타 난수는 **각각 별도 스트림**을 쓴다. 치명타 확률이나
  맞은 적 수가 달라져도 레이저 시작점의 무작위 순서가 바뀌지 않도록 한다.
- 표시용 적중 기록은 `SkillType`, 소유 `PlayerId`, 대상, 최종 피해, `IsCritical`을 담는다.
  화면은 이 결과를 재현하지 않고 읽기만 한다.

이 단위를 택한 이유는 한 번의 원형 타격이나 관통 발사가 **하나의 공격처럼 보이도록**
하고, 적 수가 늘어날 때 난수 소비와 치명타 연출 수가 무작정 증가하지 않게 하기 위해서다.
대상마다 독립 확률이 필요한 미래 스킬이 실제로 추가되면 그 스킬의 예외로 명세한다.

## 6. AttackHaste — 공격 주기 감소 버프

| 항목 | 결정 |
| --- | --- |
| Trigger | `AttackHaste` 천체의 최초 처치 확정 |
| 받는 사람 | 그 천체를 직접 처치한 `PlayerId`. 다른 플레이어에게 공유하지 않음 |
| 대상 | 그 플레이어가 현재 보유한 Breaker와 Laser의 **반복 공격 간격** |
| 수치 | `IntervalMultiplier`. 예: 0.5는 기본 간격의 절반, 공격 빈도는 2배 |
| 지속 | 정의의 `Duration`초. 전투 시간 기준이며 일시 정지 중에는 경과하지 않음 |
| 적용 | 버프를 부여한 처치가 발생한 공격에는 소급하지 않고, 다음 공격 Step부터 적용 |
| 비적용 | Laser 예고 길이·이미 발사한 공격·천체 사망 효과 피해 |

`EffectiveInterval = BaseInterval × IntervalMultiplier`. 샘플로 Breaker가 1초 간격이면
0.5초, Laser의 예고 시작이 4초 간격이면 2초가 된다. 단 Laser 예고 시간 0.4초는
그대로다. 진행 중인 공격 타이머는 버프를 얻거나 잃을 때 **진행률을 유지**한다.
예를 들어 다음 공격까지 절반을 채운 순간 0.5 버프를 얻으면, 남은 절반을 빨라진
속도로 채운다. 버프 만료도 같은 방식으로 원래 속도에 복귀한다. 공격을 즉시 한 번 더
발동시키거나 이미 소비한 빈 Tick을 되살리지 않는다.

반복 버프는 피해와 사망 효과 발생 **빈도**도 늘리므로 최종 최소 간격과 한 Step의
실행 횟수도 제한할 필요가 있다. 첫 저작 기준으로 **유효 간격은 최소 0.1초**이며,
그 아래로 내려가는 수치 조합은 0.1초로 제한한다. 이때 최대 공격 빈도는 스킬당
초당 10회다. 정의 단계에서는 0보다 크고 1보다 작은 배율만 허용한다.
전투 시간은 한 Step에 최대 0.05초씩 진행하고, 렌더 프레임 하나에 최대 네 Step을
처리한다. 긴 프레임의 초과 시간은 다음 프레임으로 이월한다. 처리하지 않은 시간을
버프 타이머나 Battle 시간에서 먼저 빼지 않는다.
레이저의 유효 간격이 예고 길이보다 짧아지면 서로 다른 예고가 겹칠 수 있지만,
각 예고는 자신의 발사 시각에 한 번씩만 피해를 준다.

## 7. GuaranteedCritical — 한시적 확정 치명타

| 항목 | 결정 |
| --- | --- |
| Trigger | `GuaranteedCritical` 천체의 최초 처치 확정 |
| 받는 사람 | 처치한 `PlayerId`. 4인 전투에서도 다른 플레이어에게 전파되지 않음 |
| 대상 | 그 플레이어의 Breaker Tick과 Laser 발사 피해 |
| 효과 | 활성화 동안 대상 공격의 최종 치명타 확률을 100%로 설정 |
| 피해 | 해당 플레이어의 **치명타 피해 배율을 한 번만** 적용 |
| 지속 | 정의의 `Duration`초. 일시 정지 중 경과하지 않음 |
| 비적용 | 폭발·연쇄 번개 피해, 골드 보상, 적에게 이미 적용된 과거 피해 |

기본 피해 2, 치명타 배율 2인 Breaker 공격은 버프 중 한 Tick의 적중 피해가 4다.
기본 피해 3인 Laser 발사는 버프 중 6이며, 한 발에 여러 적이 맞아도 모두 같은 결과다.
예고 중 버프가 끝났다면 발사할 때 기본 확률로 판정한다. 반대로 예고 후 발사 전
버프가 시작됐다면 발사에 적용된다.

## 8. 획득·중첩·만료·동시 처치

1. 효과 보유 천체의 HP가 처음 0이 되면 사망과 **마지막 유효 타격의 소유자**를 확정한다.
   이미 죽은 적의 추가 타격은 소유자를 바꾸지 않는다.
2. 한 공격 Step의 직접 피해와 적 사망을 확정한 뒤 사망 효과를 처리한다. 그 Step에 얻은
   버프는 다음 Step의 공격부터 사용한다. 한꺼번에 여러 천체가 죽으면 천체 등록 순서로
   효과를 처리하되, 아래의 합성 정책 때문에 최종 수치는 순서와 무관해야 한다.
3. **같은 종류** 버프 재획득: 배율을 곱하지 않는다. `남은 시간 = max(기존 남은 시간,
   새 Duration)`, 강도는 Haste라면 더 작은 간격 배율, 치명타라면 더 강한 치명타
   배율을 유지한다. 서로 다른 종류 두 버프는 동시에 활성화될 수 있다.
4. Haste와 확정 치명타가 동시에 활성화되어도 각각의 수치를 **한 번씩만** 적용한다.
   버프가 끝나면 그 버프만 제거하고 다른 버프의 시간·강도는 유지한다.
5. 처치자가 없는 제거와 Battle cleanup은 버프를 주지 않는다. Battle 종료·Restart는
   플레이어별 버프 시간과 실행 중인 스킬 타이머를 새 전투 상태로 초기화한다.

버프의 남은 시간이 한 Step보다 짧으면 그 **만료 시각에서도 Step을 나눈다.**
짧은 버프가 긴 Step 전체에 적용되거나, 지속 시간이 남았는데 아무 영향도 주지
못하는 일을 막는다. 예고 완료와 공격 Tick도 같은 전투 시간축에 놓는다.

## 9. 현행 구현과 남은 범위

| 대상 | `skill-only-sandbox` 구현 | 남은 범위 |
| --- | --- | --- |
| 스킬·플레이어 수치 | 스킬 형상은 `SkillStats`; 공통 수치는 `SkillCatalog.asset`의 `PlayerCombatStats` | 노드 수치 주소 연결은 별도 작업 |
| Haste | 현재 공격 진행률을 유지하며 속도만 바꾸고, 만료·공격 시각에서 Step을 분할 | Unity Play 수치 검증 |
| 긴 프레임 | `AdvanceFrame`이 최대 0.05초 Step 네 번 실행하고 나머지를 이월 | 실제 기기에서 체감·처리량 확인 |
| 치명타 | `SkillDamage`가 유효 타깃이 있는 공격당 1회 판정하며 버프 중 확정 | Unity Play·시각 표현 확인 |
| 피해 기록 | `SkillHit`에 대상·최종 피해·소유자·`IsCritical`을 남김 | 완성 게임의 연출 소비 경계 연결 |
| 난수 | Battle seed와 PlayerId로 방향·치명타 난수를 별도 생성 | 실제 전투 시드 전달·기록 연계 |
| 데이터 | 두 SO에서 Skill·Enemy·플레이어 기본 수치를 로드 | 장기 콘텐츠·저작 툴은 범위 밖 |

`SkillBattle.Advance(delta)`는 계약 시나리오용으로 전달 시간을 끝까지 분할 처리한다.
Unity 호스트는 프레임 예산과 이월 규칙이 있는 `AdvanceFrame(delta)`를 사용한다.
코어 계약과 Unity EditMode·Play의 최신 실행 결과는 별도 확인이 필요하다.

## 10. 판정 예시와 완료 기준

| 상황 | 기대 결과 |
| --- | --- |
| Breaker 한 Tick이 일반 적 셋을 맞힘, 치명타 확률 100% | 셋 모두 치명타로 같은 배율의 피해. 난수 판정 최대 1회 |
| Laser 예고 시작 시 확정 치명타 없음, 발사 전 버프 획득 | 발사에 치명타 적용 |
| Laser 예고 시작 시 버프 있음, 발사 전 만료 | 기본 확률로 판정. 예고 길이 불변 |
| Haste 0.5 도중 기본 간격 1초인 Breaker | 정상 진행 중인 타이머가 2배 속도로 차며 빈 Tick 추가 생성 없음 |
| 서로 다른 두 플레이어가 각각 버프 천체 처치 | 각자에게만 효과 적용, 서로의 피해·공격 타이머 불변 |
| 확정 치명타 + 확률 강화 + 피해 배율 강화 | 치명타 확률 100%, 최종 치명타 피해 배율 1회 적용 |
| 치명타 중 특수 천체 폭발로 일반 적 처치 | 폭발 피해에 치명타가 붙지 않음, 버프 추가 발동 없음 |
| 같은 종류 버프를 연속 획득 | 지속 시간과 강한 배율만 유지, 곱셈 중첩 없음 |
| Battle 종료 후 Restart | 버프·대기 중인 예고·타이머가 다음 전투로 넘어가지 않음 |

밸런스 수치를 결정할 때는 기본 간격·치명타 확률·배율을 따로 보고, 실제 다수 적중
상황에서 처치 수, 효과 발동 수, 한 프레임 처리 시간을 함께 측정한다. 공격 간격만
절반으로 줄여도 단순 표시 DPS 이상으로 사망 효과 빈도가 증가할 수 있기 때문이다.
